# Deterministic Retrieval Evaluation

## Purpose

Benchmark version 1 provides a repeatable regression test for the ATS hybrid
retrieval and Reciprocal Rank Fusion path. It is fully synthetic, runs without
Gemini or cloud services, and contains no production IDs or candidate data.

This benchmark measures retrieval only. It does not evaluate generated-answer
quality or claim that the small synthetic dataset represents production
traffic.

## Versioned dataset

- Benchmark: `backend/evaluation/rag_retrieval_benchmark.json`
- Synthetic fixture: `backend/evaluation/rag_retrieval_fixture.json`
- Baseline: `backend/evaluation/rag_retrieval_baseline.json`
- Current benchmark version: **1**
- Cases: **6**

The cases cover semantic phrasing, exact technical keywords, the `LLM`
abbreviation, multi-skill retrieval, an irrelevant/no-result query, and
lexical-versus-semantic behavior. Stable synthetic document references are the
relevance labels.

The fixture supplies synthetic resume chunks and deterministic vector rankings.
BM25 is calculated from those chunks by the production BM25 implementation,
then the production `hybrid_search` entry point performs RRF. This design makes
the committed regression test independent of model downloads and PostgreSQL
while still testing current lexical retrieval and fusion behavior. The existing
pgvector integration test separately verifies database cosine search.

## Metrics

All relevance is binary and retrieved document references are de-duplicated in
rank order.

- **Recall@K**: unique relevant documents found in the first K results divided
  by all relevant documents.
- **MRR**: reciprocal rank of the first relevant result.
- **nDCG@5**: binary discounted cumulative gain through rank 5 divided by the
  ideal gain for the case.
- **No-result cases**: score 1 only when retrieval is empty; otherwise score 0.

Metrics are macro-averaged across cases.

## Running the benchmark

From `backend/`:

```bash
python -m app.rag.evaluate_retrieval
python -m app.rag.evaluate_retrieval --json
```

The command exits non-zero when a metric drops more than its absolute tolerance.
Version 1 uses `0.05` for Recall@1/3/5, MRR, and nDCG@5. Floating-point values
inside the tolerance are accepted.

To inspect metrics before creating a reviewed baseline:

```bash
python -m app.rag.evaluate_retrieval --no-regression-check --json
```

## Adding cases

1. Add only synthetic text and a stable case ID to the benchmark and fixture.
2. Add the case's deterministic vector ranking.
3. Increment `benchmark_version` in the benchmark, fixture, and baseline when
   relevance judgments or corpus contents change.
4. Run without the regression check and review every ranked result.
5. Copy only the measured aggregate metrics into the baseline.
6. Run the focused tests and normal regression check.

Never add real names, contact details, resume text, production IDs, GCS paths,
or credentials.

## Known limitations

- The deterministic fixture does not measure SentenceTransformer model quality
  or production-corpus drift.
- Six synthetic cases are a regression seed, not a statistically representative
  evaluation set.
- There is no LLM judge or automated answer-quality score.
- The benchmark is intentionally not a production deployment gate.
